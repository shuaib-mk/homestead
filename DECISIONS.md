# Decisions

- Stack as specified: React + Vite + TS strict + Tailwind v4 (`@tailwindcss/vite`), because it is the fastest setup with CSS-variable tokens.
- Pixel font: Silkscreen, headings/labels only; body Space Grotesk, as it keeps content pages readable.
- Drag and drop: @dnd-kit (core + sortable) with keyboard sensor, because it gives accessible reorder for free. Move up/down buttons are the fallback.
- No Supabase MCP is configured in this workspace, so the schema is written as SQL in `supabase/migrations/` instead of applied through MCP.
- Data access through one `Repo` interface with `localRepo` and `supabaseRepo`, switched by `VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY`, so pages never know which backend they use.
- Supabase RLS is demo-grade with no auth: public read, public insert, update allowed; documented in design.md because the prompt asks for simple, and real ownership would need Supabase Auth.
- In Supabase mode, an empty database is seeded with the 5 sample homesteads on first load (guestbook entries and seed hit counts are demo-mode only, since anon cannot insert page_views by design).
- "Owner" in both modes means "this browser created it" (ids in localStorage `owned`), because there are no accounts.
- Guestbook sanitising strips tags and renders as text; links are never clickable, so no autolinking.
- Guestbook cooldown is 30s in demo mode via localStorage.
- Sample images use picsum.photos seeded URLs (free, no key); the renderer will degrade gracefully if offline.
- Vitest covers pure logic only (name validation, guestbook, later webring and export).
- Block ids and homestead ids use `crypto.randomUUID`, so ids are valid for the uuid column.
- Public page theme is driven by CSS variables (`--hs-*`) set by `pageStyle()` in `src/lib/theme.ts`; blocks only read variables, so builder preview and public page render identically. Text colour on accent/chip backgrounds is picked by luminance (`readableOn`) for contrast.
- `HomesteadView` (street sign + blocks + footer link) is the single page component reused by the public route and, later, the builder preview.
- Link and image URLs go through `safeUrl` (http/https only); anything else renders as inert text or a placeholder.
- Hit counter increments once per page load. A short-lived promise cache dedupes React StrictMode's double effect in dev.
- Webring ring = published homesteads in the same neighbourhood plus the current page, ordered by creation time. Previous/next wrap; random excludes the current page; a lone page links to itself and says so.
- Stamps wall has 12 stamps (lucide icons, ids stored in blocks): the 11 seeded ids plus `coffee`.
- "Surprise me" shows a full-screen travelling overlay (looping car on a road, 1.4s) before navigating; 300ms under reduced motion.
- `scripts/e2e-public.mjs` drives claim, counter, guestbook, owner delete, explore and 404 in headless Chromium.
- Builder is owner-only (this browser created the page). Other visitors see a "belongs to someone else" screen with links to visit or claim.
- Autosave: 600ms debounce, flushed on unmount and beforeunload. `SaveStatus` re-keys on each save so "Saved just now" pops in, then ages to "Saved N seconds ago".
- Builder layout: three columns at 1024px+ (blocks, live preview, settings), four tabs below that. Preview is the shared `HomesteadView`, so it matches the public page.
- Reorder: @dnd-kit pointer and keyboard sensors, plus move up/down buttons. Button moves glide with a small FLIP animation; drag glides via dnd-kit transitions. Moves are announced in a live region.
- Owner guestbook deletion happens in the preview's guestbook block (owner-only Delete with confirm), not a separate manager.
- Export: `src/lib/exportHtml.ts` writes the same class names as the React blocks and inlines the compiled site CSS (`index.css?inline`), so the file looks identical. Icons are inline SVG via `renderToStaticMarkup`. No scripts. Images stay as remote URLs (alt text shows offline). Fonts are not embedded: Silkscreen, Space Grotesk, Lora and Courier Prime fall back to system fonts offline. The guestbook is a dated snapshot and webring links point to the live site.
- Export code is loaded with a dynamic import so `react-dom/server` stays out of the main bundle.
